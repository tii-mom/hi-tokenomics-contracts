HI 当前合约系统详细说明

本文档说明当前 HI V1 合约系统：发行后代币如何分配、7 个合约分别负责什么、价格解锁如何推进、500万 HI 活动如何上链承载，以及合约之间如何关联。当前状态是主网已部署、主网验证已完成，合约侧只剩 Tonkeeper 资产收录等待合并和缓存刷新。

总量 10,000,000,000 HI 当前架构：7 个合约 GrowthEngine 替代 PublicSale 主网已部署并验证
50% 增长引擎：5,000,000,000 HI。用户用 TON 购买，按 USDT 价格达标分批释放。
20% 生态与活动奖励：2,000,000,000 HI。其中 16% 在 MerkleRewardVault，4% 在 CampaignWinnerVault。
12% 团队持有：1,200,000,000 HI。按 0.1 / 0.5 / 1 / 5 USDT 四个价格档释放。

核心发行原则

  • HI 总量固定：10,000,000,000 HI，精度 9 decimals。
  • 部署时一次性 mint 全部供应并完成分配。
  • 分配完成后 JettonMinter admin 被 drop，后续不能增发。
  • 不设计税费、黑名单、冻结、暂停转账、强制转账、强制燃烧。
  • 增长、团队、活动奖励的解锁条件都来自 PriceOracle 确认后的价格 level。

时间锁与价格确认

  • 当前只有 PriceOracle.confirmationDelay 这一类时间锁。
  • 测试网复演使用 30 秒，方便跑完整流程。
  • 主网部署必须使用 86400 秒，即价格达到门槛后保持 24 小时才可确认。
  • GrowthEngine、CampaignWinnerVault、MerkleRewardVault、TeamVestingVault 自身没有额外时间锁。

部署与发行流程

1. 部署 JettonMinter设置 HI metadata，部署时 admin 临时保留 mint 权限。
2. 部署业务合约部署 GrowthEngine、PriceOracle、TeamVestingVault、CampaignWinnerVault、MerkleRewardVault。
3. 配置 Jetton Wallet给四个持币业务合约注入各自的 HI Jetton Wallet 地址。
4. 完成分配按 50/16/4/12/10/5/3 把全部 HI 分配到合约和固定钱包。
5. 配置 Oracle 目标PriceOracle 绑定 GrowthEngine、TeamVestingVault、CampaignWinnerVault、MerkleRewardVault。
6. Drop Minter Admin断言各分配钱包余额和总供应后，弃权 minter admin。
7. 运营阶段oracle admin 上报价格，用户购买和 claim，reward admin 创建 Merkle batch。
8. 主网证据记录地址、交易 hash、code hash、余额、verifier 结果。

2. JettonWallet

项目说明

3. GrowthEngine

GrowthEngine 是当前的公开增长销售合约，已替代旧 PublicSale。它没有即时池，全部按锁仓释放规则处理。

项目说明
资金规模5,000,000,000 HI
购买价格1 TON = 10,100 HI
购买限制最小单笔 0.1 TON；单钱包累计最多 5000 TON。
释放规则仅 growth level 0 购买立即释放 5%；growth level 1-9 每轮释放 10%；level 10 释放最后 5%。
晚买不补购买时记录 entryLevel。level 0 和历史已确认轮次不补发，记录为 missed HI。
失败处理Jetton 转账 bounce 后回滚 claimed/sold/missed 等状态，避免半成功。
销售关闭永久关闭后，未售 HI 与 missed HI 只能 sweep 到固定项目基金钱包；已售未领取部分不能被 sweep。

4. PriceOracle

PriceOracle 是价格达标确认合约。它不负责交易定价，也不持有 HI；它只把价格达标和保持时间转换成链上的 confirmed level。

项目说明
权限oracle admin 上报价格；confirm 可以由 keeper 触发，但必须满足候选 level 与时间锁。
时间锁主网 86400 秒；测试网复演 30 秒。
增长 levelgrowthConfirmedLevel 范围 0-10，同步给 GrowthEngine、CampaignWinnerVault、MerkleRewardVault。
团队 levelteamConfirmedLevel 范围 0-4，同步给 TeamVestingVault。
不可变性confirmed level 只能递增，不能回退、不能跳级、不能超过上限。

6. CampaignWinnerVault

CampaignWinnerVault 承载 500万 HI 达成大奖池，用于最多 80 个 winner 的链上锁仓奖励。

项目说明
资金规模400,000,000 HI
winner 数量最多 80 个。
单个 winner固定 5,000,000 HI。
注册权限只能由 admin 注册，合约不处理 Telegram、邀请关系、风控判断。
entry level注册 winner 时记录当前 growthConfirmedLevel。
释放规则与 GrowthEngine 一致：level 0 注册后可领取 5%；level 1-9 每轮释放 10%；level 10 最后释放 5%。如果 winner 在第 N 轮已确认后注册，不领取 level 0 和历史 1-N 轮，只能从下一轮到 level 10 继续领取。

7. MerkleRewardVault

MerkleRewardVault 统一承载 ecosystem 和 red packet Merkle batch。链下系统负责计算资格、金额和风控；合约只验证 Merkle proof、防重复领取并发 HI。

MerkleRewardVault 总池为 1,600,000,000 HI。当前活动停用独立普惠抽奖，且链上 poolType=2 cap 为 0 HI；统一红包奖励最多占用 100,000,000 HI，生态/运营奖励使用总池剩余额度；这些不是 1.6B 之外的额外预算。

合约权限矩阵

角色权限不能做什么
admin / deployer / reward admin部署、设置业务合约 Jetton Wallet、开关 GrowthEngine、创建 Merkle batch、注册 Campaign winner、设置 migration allowlist。不能增发已 drop admin 后的 HI，不能转走用户已承诺权益，不能冻结用户钱包。
oracle admin上报 growth/team 价格，启动候选 level 计时。不能修改门槛，不能跳过 24 小时，不能回退 confirmed level。
keeper / anyone在价格候选 level 满足时间锁后调用 confirm。不能凭空确认，不能跳级。
migration wallet 1 / 2选择 admin allowlist 中的迁移目标，并迁移未承诺 HI。不能迁移用户已购、winner 已注册、Merkle 已发布额度；团队 12% 全部视为已承诺，TeamVestingVault 可迁移 HI 为 0。
用户购买 GrowthEngine、领取 GrowthEngine、领取 CampaignWinner、领取 Merkle batch。不能修改合约参数或替他人领取。

受限迁移机制

四个持币业务合约都预留迁移/救援路径：GrowthEngine、TeamVestingVault、CampaignWinnerVault、MerkleRewardVault。当前 V1 已确认接受以下模型：

规则说明
目标 allowlist管理员先通过 Set*MigrationTargetAllowed 把目标地址加入 allowlist。
双迁移钱包两个指定 migration wallet 任意一个都可以选择 allowlist 中的目标并发起迁移。
只能迁移未承诺 HI未售、未注册、未发布 batch 的合约余额可以迁移；用户权益和已承诺余额不能迁移。团队分配全部已承诺，因此 TeamVestingVault 只保留 allowlist/target 选择，不允许迁移 HI。
不做 code-hash checkV1 不加入 code-hash check 或 timelock governance；目标地址需要通过部署文档、多签流程和审计记录控制。

这是高信任运维权限，不是用户资金提现权限。主网应使用多签或强隔离钱包作为 migration wallet，并公开每次 allowlist 与迁移动作。
